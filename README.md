# Gold Volatility Prediction Using Commodity and Macroeconomic Indicators

## Overview

This project investigates whether historical commodity, financial-market, and macroeconomic data can be used to forecast the gold market.

The dataset was built by combining daily market data from Yahoo Finance with macroeconomic data from the Federal Reserve Economic Data (FRED) database. Three models forecast **gold's near-term realized volatility** (`vol_target_5d`, `vol_target_22d`) from the same features, the same sample, and the same splits:

- **Lasso** — a linear model with L1 regularization, which also selects features by shrinking coefficients to zero
- **XGBoost** — learns nonlinear relationships from engineered tabular features
- **LSTM** — learns from 30-day sequences of those same features

Each is measured against the same two references: a persistence baseline, and **HAR**, the standard linear benchmark for realized-volatility forecasting.

**Why volatility rather than price.** The project began by predicting the next day's gold *return*. That target proved effectively unpredictable from this data: the models reached R² ≈ 0, and a direction classifier scored ROC-AUC ≈ 0.51 against a 0.50 no-skill line. That is a genuine finding about market efficiency rather than a modelling failure, and it is documented as such. Volatility, by contrast, clusters — calm follows calm, turbulence follows turbulence — and is therefore forecastable, so the models were pivoted to it.

Methodology, results, significance testing, ablations, and interpretation are written up inline in the three model notebooks under [notebooks/](notebooks/); each follows the same twelve-section structure so they can be read side by side.

## Research Questions

1. Are next-day gold returns predictable at all, and if not, what is?
2. Which model forecasts gold volatility most accurately, and is its advantage over standard benchmarks statistically significant?
3. Does macroeconomic data improve performance compared with gold's own history alone?
4. Does forward-looking implied volatility (the CBOE Gold Volatility Index) add information beyond realized history?
5. How much does the choice of volatility estimator affect the conclusions?
6. How does model performance change after hyperparameter tuning?

## Dataset

### Sources

- **Yahoo Finance** — gold, commodities, currencies, equity-market data, volatility indices, and trading volume
- **Federal Reserve Economic Data (FRED)** — inflation expectations and U.S. Treasury yields

There is no ready-made dataset for this; it is generated by the scripts in this repository and can be rebuilt from scratch.

### Size

After cleaning and feature engineering, `data/daily_commodity_market_data_cleaned.csv` contains:

- **5,029 daily observations**, 22 January 2004 through 30 July 2026
- **29 model features** — 21 macro / cross-asset, 3 HAR, and 5 implied-volatility
- **Volatility targets** at 5 and 22 trading days, plus the retained `tomorrow_gold_log_return` target that documents the negative return result

The volatility models are filtered to **3 June 2008** onward, the inception date of the CBOE Gold Volatility Index, which leaves **4,309 usable rows** beginning 27 June 2008 once every feature has a value. That cut also excludes the 2004–2007 gold range data, where 38–55% of days report `High == Low` and the range series measures only about a third of close-to-close volatility — an artifact of thin early electronic-session coverage, not a calm market. The full history is retained in the CSV.

### Market and Macroeconomic Inputs

- Gold open, high, low, close, and volume
- Crude oil, silver, copper, platinum
- U.S. Dollar Index, EUR/USD, S&P 500
- VIX Index
- **GVZ Index** — CBOE Gold Volatility Index (implied volatility)
- **OVX Index** — CBOE Crude Oil Volatility Index
- 10-year breakeven inflation
- U.S. 2-year and 10-year Treasury yields

### Engineered Features

- Gold 1-day, 5-day, and 20-day log returns
- Gold 5-day and 20-day rolling volatility
- Gold closing position within the daily high-low range
- Gold volume change and relative volume
- Daily returns for the other commodities and financial assets
- Daily VIX change
- Changes in inflation expectations and Treasury yields
- The 10-year minus 2-year yield-curve slope, and its daily change
- **HAR components** — log volatility averaged over 1, 5, and 22 days
- **Implied-volatility features** — log GVZ, GVZ change, 5-day mean GVZ, log OVX, and the variance risk premium (implied minus realized)

### Volatility Estimator

The volatility target uses a daily **Yang-Zhang** proxy, `ln(O/C₋₁)² + RS`, where `RS` is the Rogers-Satchell intraday term. Unlike the Parkinson high-low estimator used in earlier iterations, this accounts for the overnight gap — which matters because gold trades nearly around the clock. Over 2008+, Parkinson measures 0.68× close-to-close volatility while Yang-Zhang measures 0.78×.

The Parkinson series is retained under a `park_` prefix so the choice can be reported as a controlled ablation.

## Repository Structure

```text
volatility_prediction/
├── notebooks/
│   ├── lasso_gold_prediction.ipynb          # Lasso volatility model
│   ├── xgboost_gold_prediction.ipynb        # XGBoost volatility model
│   └── lstm_gold_prediction.ipynb           # LSTM volatility model
├── scripts/
│   ├── create_dataset.py                    # downloads raw data (Yahoo Finance + FRED)
│   └── process_dataset.py                   # cleaning + feature engineering
├── app/
│   └── app.py                               # demo: pick a date, get a forecast
│                                            # and a position size
├── data/
│   ├── daily_commodity_market_data.csv         # raw download
│   └── daily_commodity_market_data_cleaned.csv # cleaned + engineered, model input
├── results/                                 # exported metrics and predictions,
│                                            # one lasso_vol_* / xgboost_vol_* /
│                                            # lstm_vol_* set per model
├── report_figures/                          # every figure, written by the notebooks
├── Dockerfile                               # container for the demo app
├── docker-compose.yml
├── README.md
└── requirements.txt
```

The three model notebooks are self-contained and share no imported module, so each runs top to bottom on its own. Each follows the same twelve-section structure — benchmarks, tuning, Diebold-Mariano significance tests, feature importance, both ablations, a volatility-direction classifier, and a one-year walk-forward backtest — and uses identical feature lists, sample filters, splits, and metric definitions. That is what makes the three models directly comparable.

Paths inside the notebooks are relative to `notebooks/`, so run Jupyter with that
folder as the working directory. The scripts and the app resolve their own paths
and can be run from anywhere.

## Installation

### 1. Create a virtual environment

#### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

#### macOS or Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 2. Install dependencies

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## Usage

### Rebuild the dataset (optional)

`data/daily_commodity_market_data_cleaned.csv` is committed, so the notebooks run
without this step. To regenerate it from source:

```bash
python scripts/create_dataset.py    # writes data/daily_commodity_market_data.csv
python scripts/process_dataset.py   # writes data/daily_commodity_market_data_cleaned.csv
```

### Run the models

```bash
jupyter lab notebooks/
```

Open any of `lasso_gold_prediction.ipynb`, `xgboost_gold_prediction.ipynb`, or
`lstm_gold_prediction.ipynb` and run the cells in order. Each writes its metrics
and predictions to `results/` and its figures to `report_figures/`.

### Run the demo app

```bash
streamlit run app/app.py
```

Or with Docker:

```bash
docker compose up --build
```

The app trains an XGBoost model on data strictly before the date you pick,
forecasts the next session's volatility, and converts that into a position size
for a chosen annual risk target. It is a course demo, not investment advice.

## Data Sources

- Yahoo Finance
- Federal Reserve Economic Data (FRED)

Because these sources update over time, regenerating the dataset produces a later end date than the version used in the reported experiments, and results shift slightly.
